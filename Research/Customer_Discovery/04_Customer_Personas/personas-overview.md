## چیزی که هر دو مشترک دارن (هسته محصول Atlas)

هر دو پرسونا، صرف‌نظر از نوع کسب‌وکار، دقیقاً روی یک نقطه درد اصلی گیر کرده‌اند:

> **"من نمی‌دونم الان واقعاً چقدر سود می‌کنم — و هر بار باید همون اطلاعات رو چند جا دستی وارد کنم."**

این دو مورد باید **هسته مشترک** (Core Layer) هر دو مسیر محصول باشه:
1. **داشبورد مالی شفاف و لحظه‌ای** (فروش، سود واقعی، نقدینگی، بدهی/چک)
2. **حذف ورود دستی و تکراری داده** (یکپارچه‌سازی کانال‌های ورودی اطلاعات به یک نقطه)

هر دو همچنین:
- به دلیل نوسان بازار ایران (ارز برای خرده‌فروشی، فصلی‌بودن برای سالن)، **درآمد نامنظم و پیش‌بینی‌ناپذیر** دارن.
- نسبت به **تصمیم‌گیری خودکار بدون تایید دستی** محتاط‌ان — هر دو می‌خوان کنترل نهایی دست خودشون بمونه.
- **سواد فنی محدود** دارن و ابزار باید فوق‌العاده ساده باشه، وگرنه کنار گذاشته می‌شه.
- ترجیح می‌دن **هزینه ماهانه کم** بدن تا تعهد سنگین بلندمدت.

## چیزی که این دو رو از هم متفاوت می‌کنه (نیاز به مسیر جدا)

| بُعد تفاوت | رضا (خرده‌فروشی) | مریم (سالن) |
|---|---|---|
| واحد اصلی کسب‌وکار | **کالا** (موجودی فیزیکی، چندکاناله) | **زمان/نوبت** (ظرفیت محدود روزانه) |
| متغیر اصلی قیمت‌گذاری | نرخ ارز روزانه | ترکیب مواد مصرفی + پورسانت پرسنل |
| ریسک اصلی عملیاتی | فروش کالای ناموجود به مشتری آنلاین | تداخل نوبت دو مشتری هم‌زمان |
| نوع رابطه با مشتری | تراکنشی، گاهی تکراری | رابطه‌محور، وابسته به اعتماد فردی (آرایشگر/مشتری) |

این تفاوت‌ها یعنی **فیچرهای لایه دوم محصول** (بعد از هسته مشترک مالی) باید برای هر مسیر جدا طراحی بشن:
- مسیر خرده‌فروشی → تمرکز روی همگام‌سازی موجودی چندکاناله + پیشنهاد قیمت
- مسیر سالن → تمرکز روی نوبت‌دهی یکپارچه + محاسبه‌گر سود خدمت + پروفایل مشتری

## پیامد برای معماری محصول

```
         ┌─────────────────────────────┐
         │   هسته مشترک (Core Layer)    │
         │  داشبورد مالی + حذف ورود      │
         │      دستی تکراری داده         │
         └───────────┬─────────────────┘
                      │
        ┌─────────────┴─────────────┐
        │                           │
┌───────▼────────┐         ┌────────▼────────┐
│ مسیر خرده‌فروشی │         │   مسیر سالن      │
│ - همگام‌سازی    │         │ - نوبت‌دهی        │
│   موجودی        │         │ - محاسبه سود      │
│ - پیشنهاد قیمت  │         │   خدمت            │
│                 │         │ - پروفایل مشتری  │
└─────────────────┘         └───────────────────┘
```

این ساختار به شما اجازه می‌ده MVP رو با **یک هسته مشترک** بسازید و بعد بسته به بازخورد بازار، تصمیم بگیرید کدوم مسیر (یا هر دو) رو زودتر عمیق‌تر توسعه بدید.
